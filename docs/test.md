# 動作確認の方法

最終更新: 2026-10-08

自動テストは無い。型チェックと、以下の手動確認で「正しく動いている」と判断する。

## 1. 型チェック

```bash
cd ~/root/personal/project/local-embedding-search
npm run typecheck
```

→ 何もエラーが出なければ OK

## 2. ターミナルだけで確認（ブラウザなし）

```bash
npm run build-index
npm run search -- "数学が得意な人が出てくるミステリー"
npm run search -- "魔法学校が舞台のファンタジー"
```

→ 2回目以降の `build-index` は `再利用 5`。検索はそれぞれ次が1位になる。

| 検索文 | 1位 | 類似度（q8 版、2026-10-08） |
|---|---|---|
| 数学が得意な人が出てくるミステリー | 容疑者Xの献身 | 0.8451 |
| 魔法学校が舞台のファンタジー | ハリー・ポッターと賢者の石 | 0.8949 |

## 3. ブラウザで確認

`npm start` して <http://localhost:8000> を開き、上から順に触る。

1. **ヘッダー**: 右上が `● multilingual-e5-base · q8 · cpu · offline`（点が緑）
2. **検索**: 開いた直後に例文で検索済みになっていて、5件が類似度順に並ぶ。1位だけ青。
   バーは1位が一番長く、5位がほぼ空。右の「処理の記録」に 768 次元・ミリ秒・`5 行 · 再Embedding 0` が出る
3. **登録**: 「登録」タブでタイトルと説明を入れると、「モデルへの入力」に `passage: タイトル↵説明` が即座に出る。
   「登録」を押すと右に「保存済み」とベクトル・SQL が出る。同じタイトルでもう一度押すと赤字で「同じタイトルの本がすでにあります」
4. **登録した本が検索に出る**: 例えば「星を継ぐもの / 月で見つかった五万年前の遺体の謎を、科学者たちが解き明かしていくSF小説。」を登録し、
   検索で「宇宙や科学の謎を解く話」と入れると、それが1位になる
5. **データベース**: 「データベース」タブで全行が出る。検索欄に「小説」と入れると3件に減り、下の SQL が
   `… WHERE title LIKE '%小説%' OR description LIKE '%小説%';` に変わる。何も合わない文字なら「該当なし」
6. **ベクトル表示**: 行のタイトルを押すと右側がその本に切り替わる。「全 768 個」を押すと 768 個の数値が並ぶ
7. **削除**: ゴミ箱を押して確認ダイアログで OK すると行が消え、件数が減る（手順 4 で足した本を消して元に戻す）
8. **スマホ幅**: ブラウザの幅を狭めても横にはみ出さない（表だけは枠の中で横スクロール）

サーバーのターミナルには、検索・登録のたびに `[Embedding]` のログと `[Search] 1. 0.8451 容疑者Xの献身` のような行が出る。

## 4. オフラインで動くことの確認

1. Wi-Fi を切る
2. `npm start` して、検索・登録ができる

モデルが `models/` に無いときは、ネットに取りに行かずに
`モデルを読み込めません（… env.allowRemoteModels=false and file was not found locally …）` で止まる（2026-10-08 に確認）。

## 補足: Claude に確認させるとき

ヘッドレス Chrome で撮る・操作する。`--window-size=390,…` は Chrome の横幅の下限に引っかかって
スマホ幅の確認にならないので、幅 390px の iframe に入れたページを撮る。
画面の操作は Chrome DevTools Protocol（`--remote-debugging-port`）で JS を実行して行った。
