# 動作確認の方法

最終更新: 2026-10-08

自動テストは無い。型チェックと、以下の手動確認で「正しく動いている」と判断する。

## 1. 型チェック

```bash
cd ~/root/personal/project/local-embedding-search
npm run typecheck
```

→ 何もエラーが出なければ OK

## 2. ターミナルだけで確認（ブラウザなし）

```bash
npm run build-index
npm run search -- "数学が得意な人が出てくるミステリー"
npm run search -- "魔法学校が舞台のファンタジー"
```

→ 2回目以降の `build-index` は `再利用 352`。検索は上位 10 件が出て、次のようになる（352 冊、q8 版、2026-10-08）。

| 検索文 | 上位 |
|---|---|
| 数学が得意な人が出てくるミステリー | 1. 数学ガール 0.8526 / 2. 容疑者Xの献身 0.8451 / 3. 博士の愛した数式 0.8444 |
| 魔法学校が舞台のファンタジー | 1〜3. ハリー・ポッターの3冊（賢者の石 0.8949） |
| 宇宙飛行士の話 | 1. 宇宙兄弟 / 2. 火星の人 |
| プログラムを読みやすく書く方法 | 1. Clean Code / 2. リーダブルコード |
| 高校生の部活の青春 | 1. 桐島、部活やめるってよ / 2. 一瞬の風になれ |

うまくいかない例もある（Embedding 検索の性質として見ておくとよい）:
- 「戦争の悲惨さを伝える本」→ 1位はタイトルに「戦争」を含む『戦争と平和』で、『火垂るの墓』などは3位以内に入らない
- 「お金の勉強」→ 1位は『金持ち父さん貧乏父さん』だが、2位に関係の薄い『線形代数入門』が来る

## 3. ブラウザで確認

`npm start` して <http://localhost:8000> を開き、上から順に触る。

1. **ヘッダー**: 右上が `● multilingual-e5-base · q8 · cpu · offline`（点が緑）
2. **検索**: 開いた直後に例文で検索済みになっていて、`上位 10 件 / 352 冊` と出て10件が類似度順に並ぶ。1位だけ青。
   バーは1位が一番長く、10位がほぼ空。右の「処理の記録」に 768 次元・ミリ秒・`352 行 · 再Embedding 0`・`352 冊 · 上位 10` が出る
3. **登録**: 「登録」タブでタイトルと説明を入れると、「モデルへの入力」に `passage: タイトル↵説明` が即座に出る。
   「登録」を押すと右に「保存済み」とベクトル・SQL が出る。同じタイトルでもう一度押すと赤字で「同じタイトルの本がすでにあります」
4. **登録した本が検索に出る**: データに無い本、例えば「銀河ヒッチハイク・ガイド / 地球が取り壊された日に、宇宙人の友人と宇宙を旅することになった男のSFコメディ。」を登録し、
   検索で「宇宙を旅するコメディ」と入れると、それが1位になる（0.8396、2位は『2001年宇宙の旅』）
5. **データベース**: 「データベース」タブで全行が出る。検索欄に「小説」と入れると 119 件に、「数学」なら 10 件に減り、下の SQL が
   `… WHERE title LIKE '%小説%' OR description LIKE '%小説%';` に変わる。何も合わない文字なら「該当なし」
6. **ベクトル表示**: 行のタイトルを押すと右側がその本に切り替わる。「全 768 個」を押すと 768 個の数値が並ぶ
7. **削除**: ゴミ箱を押して確認ダイアログで OK すると行が消え、件数が減る（手順 4 で足した本を消して元に戻す）
8. **スマホ幅**: ブラウザの幅を狭めても横にはみ出さない（表だけは枠の中で横スクロール）

サーバーのターミナルには、検索・登録のたびに `[Embedding]` のログと `[Search] 1. 0.8526  数学ガール` のような行が出る。

## 4. オフラインで動くことの確認

1. Wi-Fi を切る
2. `npm start` して、検索・登録ができる

モデルが `models/` に無いときは、ネットに取りに行かずに
`モデルを読み込めません（… env.allowRemoteModels=false and file was not found locally …）` で止まる（2026-10-08 に確認）。

## 補足: Claude に確認させるとき

ヘッドレス Chrome で撮る・操作する。`--window-size=390,…` は Chrome の横幅の下限に引っかかって
スマホ幅の確認にならないので、幅 390px の iframe に入れたページを撮る。
画面の操作は Chrome DevTools Protocol（`--remote-debugging-port`）で JS を実行して行った。
